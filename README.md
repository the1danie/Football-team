# ⚽ Football Team Duty Bot

Telegram-бот, который перед каждой игрой или тренировкой распределяет обязанности между игроками, подтвердившими участие: мячи, вода, манишки, стирка манишек.

- распределяет только между теми, кто нажал «✅ Буду»;
- мячи достаются только игрокам с машиной;
- в приоритете тот, кто выполнял эту обязанность реже и у кого меньше обязанностей в целом;
- если игрок передумал идти, его обязанность автоматически переходит другому;
- игроки могут меняться обязанностями;
- напоминания лично ответственным и в общий чат;
- статистика по команде и по каждому игроку.

## Как пользоваться

### Первый запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) и пропишите его в `ADMIN_IDS`.
3. Запустите бота (см. ниже).
4. Добавьте бота в общий чат команды и отправьте там **`/bindchat`** — туда будут публиковаться игры.
   Чтобы бот видел нажатия кнопок, права администратора ему не нужны.
5. Каждый игрок один раз пишет боту в личку `/start`: имя и есть ли машина.
   Без этого бот не сможет присылать личные напоминания и предложения обмена.

### Администратор (в личке с ботом)

| Кнопка | Что делает |
|---|---|
| ➕ Создать игру | дата → время → игра/тренировка → место (необязательно) → публикация в чат |
| 📅 Текущая игра | карточки ближайших игр с кнопками управления |
| 👥 Участники | кто будет / не будет / не знает, сколько машин |
| 🎯 Распределить обязанности | распределить вручную (или пересчитать заново) |
| ✏️ Изменить назначение | назначить конкретного игрока на обязанность или снять |
| ❌ Отменить игру | отмена с уведомлением в чат и ответственным |
| 📊 Статистика | сколько обязанностей у каждого |

Дополнительно: `/duties`, `/add_duty 🩹 Аптечка` (с машиной: `/add_duty 🎈 Насос машина`), `/toggle_duty <id>`.

### Игрок

- В чате команды под игрой: **✅ Буду / ❌ Не буду / 🤔 Пока не знаю**.
- После распределения в чате появляется сообщение с обязанностями и кнопкой **🔄 Поменяться** — она открывает личку с ботом: выбираешь участника, он получает предложение и может согласиться или отказаться. Можно предложить обязанность и тому, у кого её нет.
- **👤 Мой профиль** — сменить имя или наличие машины. Если убрать машину, твои «машинные» обязанности перейдут другим.

### Автоматика

| Когда | Что | Настройка |
|---|---|---|
| за 5 ч до начала | автоматическое распределение (отчёт придёт администраторам) | `AUTO_DISTRIBUTE_HOURS`, `0` — только вручную |
| за 3 ч | личное напоминание каждому ответственному | `PERSONAL_REMINDER_HOURS` |
| за 2 ч | напоминание в общий чат со списком ответственных | `GROUP_REMINDER_HOURS` |
| через 3 ч после начала | игра помечается завершённой | `FINISH_AFTER_HOURS` |

Если игру создали позже момента автораспределения, бот распределит обязанности перед личным напоминанием, чтобы люди успели отметиться.
Если после распределения пришёл новый игрок, а какая-то обязанность осталась без исполнителя (например, не было никого с машиной), бот сразу назначит её ему.

## Алгоритм распределения

```
score = (сколько раз игрок выполнял эту обязанность) × 3
      + (сколько всего обязанностей у игрока)
      + 2, если у игрока была обязанность на прошлой игре
```

Чем меньше `score`, тем выше приоритет. Все обязанности игры распределяются за один проход
так, чтобы суммарный `score` был минимальным (задача о назначениях, венгерский алгоритм). Поэтому
последняя обязанность не достаётся по остаточному принципу тому, кто делал её в прошлый раз.
Две обязанности на одного человека бывают, только если участников меньше, чем обязанностей.
«Машинные» обязанности получают только игроки с машиной; если таких нет — бот предупреждает
и просит назначить вручную. Отменённые игры в статистике не учитываются.

Код алгоритма — `bot/services/distribution.py`, он не зависит от Telegram и БД.

## Запуск

### Docker (VPS)

```bash
cp .env.example .env   # впишите BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
```

Поднимутся PostgreSQL и бот. Таблицы и стандартные обязанности создаются автоматически при старте.

### Локально (SQLite)

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env   # DATABASE_URL=sqlite+aiosqlite:///football.db
python -m bot
```

### Тесты

```bash
pytest
```

Тесты покрывают алгоритм, сервисный слой на реальной БД и сквозной сценарий через настоящий
диспетчер aiogram с фейковым Telegram API: регистрация → создание игры → отметки → распределение →
отказ → обмен → ручное назначение → статистика → напоминания → отмена.

## Структура

```
bot/
  __main__.py         запуск: python -m bot
  config.py           настройки из переменных окружения
  models.py           таблицы: users, games, game_participants, duties, assignments, swap_requests
  services/
    distribution.py   алгоритм распределения (без БД)
    games.py          игры, участники, назначения, обмены, статистика
  handlers/           хендлеры Telegram: профиль, админка, чат, обмены, статистика
  notifier.py         отправка и обновление сообщений
  scheduler.py        автораспределение, напоминания, завершение игр (раз в минуту)
  texts.py, keyboards.py
tests/
```

## Ограничения MVP

- Одна команда на одного бота (один общий чат).
- Схема БД создаётся через `create_all`; при изменении моделей в будущем стоит подключить Alembic.
- Состояние диалогов (создание игры, ввод имени) хранится в памяти — при перезапуске бота
  незавершённый диалог нужно начать заново. Сами данные хранятся в БД.
